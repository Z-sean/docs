## 核心定位

- 选择器的价值不在“能选中”，而在于用最小副作用、最高清晰度，把样式**准确绑定**到结构和状态。
- 常见有基础选择器（标签、类、id、*）、关系选择器（后代、子代、相邻兄弟、通用兄弟）、属性选择器、伪类、伪元素。

> 选择器一般直接影响三件事：
>
> 1. 可维护性：选择器越依赖层级和位置，结构一变越容易失效。
> 2. 复用性：**类选择器适合组件复用，id 更偏唯一标识**，不适合大规模样式系统。
> 3. 语义表达：:focus-visible、:disabled、::before 这类写法，本质是在描述状态与界面语义，而不是纯视觉。

```css
.page .content .list li span {
  color: #333;
}
```

- 这种写法就对于层级结构强依赖，不利于后续维护

```css
.list-item__text {
  color: #333;
}

.list-item:hover .list-item__text {
  color: #111;
}
```

- 类名表达职责，不绑死结构
- 状态写在上下文中，该DOM不牵连样式
- 选择器更短，层叠可控

## 常见错误习惯

- 滥用id选择器
- 选择器写太深
  - .a .b .c .d 往往说明你在依赖页面结构
- 混淆伪类/伪元素
  - `:hover、:focus` 是状态；`::before、::after` 是生成内容，职责不同
- 选择器边界模糊
  - `[class*="btn"]`边界模糊，除了明确知道含义，一般不建议使用
