## 是什么？

- `Flex` 布局的逻辑是一种“一维弹性空间分配算法”，它将元素尺寸的绝对控制权交还给容器，通过主轴和交叉轴动态瓜分或挤压可用空间
- `Flex`是一套基于内容最小尺寸（min-content）与可用空间动态博弈的弹性分配系统

## 核心定义

- 主轴与交叉轴
  - `Flex` 的思维起点是“流动方向”。主轴是项目的排列方向（由 `flex-direction` 决定），交叉轴**永远垂直于主轴**。 改变主轴方向不仅改变了视觉流，更改变了所有对齐属性（如 `justify-content` 和 `align-items`）。
- 弹性三元素
  - `flex-basis` (基准值)：它在分配空间前，预估项目的初始主轴尺寸。它的优先级高于 width/height。
  - `flex-grow` (放大比例)：当容器有剩余空间时，按比例瓜分空间。
  - `flex-shrink` (缩小比例)：当容器空间不足时，按比例挤压项目以避免溢出。
- 在 `Flex` 模型中，元素的最终尺寸不仅仅由 `width` 决定，而是 `flex-basis`、内容固有尺寸以及容器剩余空间共同作用的结果。浏览器渲染引擎在计算布局时，会基于“尽可能展示内容”的原则，给予内容本身的尺寸极高的优先级。
- `Flex` 项目的 `min-width` 和 `min-height` 默认值是 auto，而不是 0。这意味着，无论 `flex-shrink` 设置得多大，元素都绝对不会收缩到比其内部不可断行内容（如长单词、连续数字、图片或未截断的表格）更小的尺寸。

---

```css
.form-container {
  display: flex;
  /* 设置合理的间距，避免使用 margin 带来的逻辑复杂化 */
  gap: 12px; 
}

.input-box {
  /* 等同于 flex: 1 1 0%; 吸收所有剩余空间，且在空间不足时允许被压缩 */
  flex: 1;
  /* 破除默认的最小宽度限制，防止内容过长撑破容器 */
  min-width: 0; 
}

.submit-btn {
  /* 不放大，不缩小，以内容或固定尺寸为准 */
  flex: none; 
}
```

```css
.flex-item-text {
  flex: 1;
  /* 核心：覆盖默认的 min-width: auto，剥夺内容撑开容器的特权 */
  min-width: 0; 
  /* 如果是纵向列布局被撑开，则对应使用 min-height: 0 */
  
  /* 内部再处理文本截断 */
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

## 常见错误排查

- 文本截断失效
  - 在 flex 子项中使用 `text-overflow: ellipsis` 经常失效，甚至撑爆容器。这是因为 `flex items` 的默认 `min-width` 为 `auto`（即内容最小宽度）。解决方案是给包含文本的 flex 子项显式设置 `min-width: 0` 或 `overflow: hidden`，强行重置其最小尺寸限制。
- 图片被拉伸变形
  - Flex 容器默认的交叉轴对齐属性是 `align-items: stretch`。如果图片元素没有设定固定高度，它会被拉伸以填满交叉轴的高度。解决方案是在容器上显式设置 `align-items: center` 或在图片项目上设置 `align-self: flex-start`。
- 等分布局不等分
  - 给三个子项都设置了 flex: 1，但因为内部字数不同，导致三者实际宽度不一。这是因为单写 flex: 1 时，某些老旧浏览器的解析或内部元素的 `min-content` 差异依然会影响基础尺寸。解法：强制统一基础起跑线，写全 `flex: 1 1 0%`（或配合 width: 0），确保真正的刚性等分
- 元素高度被意外拉伸变形
  - `Flex` 容器的交叉轴对齐默认值是 `align-items: stretch`。如果侧边栏与主区域并排，内容较少的一侧会被强制拉伸到与最高者齐平。解法：如果不需要这种行为，必须显式在容器上覆盖默认值，例如 `align-items: flex-start`。
