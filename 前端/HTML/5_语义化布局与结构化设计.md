## 语义化布局的核心
- 语义化布局的本质，不是把 div 换成一堆新标签，而是让页面结构准确表达“这块内容在整页里扮演什么角色”。

## 核心定义
- `header/footer` 表示头部与尾部区域，
- `nav` 表示导航，`main` 表示页面主体唯一核心内容，
- `article` 表示可独立传播的完整内容单元，
- `section` 表示主题分组，
- `aside` 表示补充信息。
所谓“页面骨架”，就是先按内容职责划分区域，再往里填组件和样式。

### 语义说明
- `main` 通常一页只该有一个；
- `article`强调独立成篇；
- `section` 必须有主题，常配标题；
- `aside`是补充，不是随便放右边栏就算。

```html
<header></header>
<nav></nav>
<main>
  <article>
    <h2>文章标题</h2>
  </article>
  <aside>推荐阅读</aside>
</main>
<footer></footer>
```

## 常见实践问题
1. 全页面只用 div
    - 问题不在能不能跑，而在结构失语。
    - 解决：先按内容职责选语义标签，再用 div 做局部布局包裹。

2. section、article、aside 混用
    - 判断法很直接：能单独成立的是 article；同主题分组用 section；补充说明、推荐、广告用 aside。

3. 结构靠视觉猜
    - 两栏布局不等于一定有 aside，关键看右侧是不是补充内容，而不是“它长在右边”。
