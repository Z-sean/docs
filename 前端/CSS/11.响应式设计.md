## 核心定义
- 响应式设计是建立一套基于视口（Viewport）和相对单位的流式计算系统，让界面自然适配容器。
- 视口定义
  - 移动端，网页的物理像素与 CSS 像素并不等价。如果不设置 `<meta name="viewport">`，手机浏览器会默认以约 980px 的桌面宽度渲染页面然后强行缩放。配置 width=device-width 是将布局视口（Layout Viewport）强行对齐设备的理想视口
- 相对单位
  - `vw/vh`：**与屏幕尺寸强绑定**。常用于宏观的大尺寸区块划分或流体排版。
  - `rem (Root em)`：**相对根节点（html）的字体大小**。它的核心价值在于**可访问性 (a11y)**——当视障用户在浏览器全局设置中调大基础字号时，基于 rem 的页面会整体等比放大，而写死 px 的页面会彻底破坏用户的阅读体验。
  - `em`：**相对父级（或自身）的字体大小**。极其适合用来开发高内聚的组件（如 Button），让组件内的 padding、icon 随组件字号动态缩放。
- 移动优先
  - 使用 min-width 断点从小屏幕写到大屏幕，是性能优化的要求

## 常见错误指南
- 移动端 100vh 滚动条陷阱
  - 排查思路：在 iOS Safari 或安卓 Chrome 中，设置 height: 100vh 的全屏容器底部往往会被浏览器的地址栏/操作栏遮挡。因为传统的 vh 计算并未扣除这些动态工具栏的高度。
  - 解法：将 100vh 替换为 100dvh（Dynamic Viewport Height），浏览器会自动处理工具栏展开/收起时的真实可用高度。
- 滥用百分比 % 导致高度塌陷
  - 排查思路：百分比高度计算的前提是父元素必须有明确的高度宣告（绝对值或继承到的具体尺寸）。如果父元素高度由内容撑开（height: auto），子元素的百分比高度将直接失效并降级为 auto。
- 图片溢出破坏网格
  - 排查思路：用户上传的高分辨率图片直接撑爆了响应式布局，导致移动端出现横向滚动条。
  - 解法：永远在全局基础样式（Reset CSS）中设置 img { max-width: 100%; height: auto; display: block; }
